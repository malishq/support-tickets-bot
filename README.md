# Служба поддержки — Telegram-бот с тикетами

Бот принимает обращения клиентов, превращает их в тикеты с номерами и статусами, передаёт операторам и возвращает ответы клиенту в тот же чат. Операторы работают из личных сообщений с ботом или из группы с топиками, где на каждое обращение создаётся свой топик.

Демо: [@helpdesk_tickets_demo_bot](https://t.me/helpdesk_tickets_demo_bot)

Демо для портфолио: компания вымышленная, цены и имена — примеры.

## Что умеет

### Клиент

- `/start` — приветствие и меню: «Новое обращение», «Мои обращения», «Частые вопросы».
- Новое обращение по шагам: категория (оплата, доставка, техническая проблема, другое) → описание → необязательное фото или файл → подтверждение → номер тикета вида `#1001`.
- Автоответ из базы частых вопросов (`data/faq.json`): если описание совпало по ключевым словам, бот сначала предлагает готовый ответ с кнопками «Помогло» и «Нужен оператор». Так же бот отвечает на любое свободное сообщение, когда у клиента нет открытого обращения.
- Пока обращение открыто, все сообщения клиента (текст, фото, файлы) уходят операторам; бот отмечает их реакцией 👌.
- Статусы: открыт → в работе → ждём ответа клиента → закрыт. Клиент получает уведомление, когда оператор взял обращение, и сами ответы операторов.
- После закрытия — оценка от 1 до 5 и необязательный комментарий. Переоткрыть обращение можно в течение 24 часов (настраивается).
- «Мои обращения» — список со статусами, у каждого — карточка и история переписки.

### Оператор

- Карточка нового тикета приходит каждому оператору из `OPERATOR_IDS` и, если задан `SUPPORT_CHAT_ID`, в группу с топиками: на каждый тикет создаётся свой топик `#1001 · Оплата · Имя клиента`.
- Кнопки на карточке: «Взять в работу», «Закрыть», «Шаблоны ответов» (быстрые ответы из `data/templates.json` с подстановкой имени клиента и оператора), «История».
- Ответ клиенту — ответом (reply) на карточку или на пересланное сообщение клиента; в группе с топиками достаточно написать в топик тикета. Текст, фото и документы работают в обе стороны.
- `/tickets` — список обращений с фильтрами по статусу и категории (кнопками, с постраничной навигацией), `/ticket 1001` — карточка и история.
- `/stats` — обращений за день и за 7 дней, среднее время первого ответа и закрытия, средняя оценка, нагрузка по операторам.
- `/ban` и `/unban` — блокировка клиента по id пользователя, номеру обращения или ответом на его сообщение (только для `ADMIN_IDS`).
- Напоминание операторам о тикетах, которые ждут ответа дольше `REMINDER_MINUTES` минут (фоновая задача).

### Хранение

SQLite через aiosqlite: пользователи, операторы, тикеты, сообщения, оценки и привязка карточек к тикетам. Таблицы создаются при первом запуске, файл базы — `DB_PATH` (по умолчанию `data/support.db`).

## Стек

Python 3.9+, aiogram 3.22, aiosqlite, python-dotenv, pytest. Чистая логика (переходы статусов, подбор ответа из FAQ, статистика, форматирование карточек) вынесена в `bot/services/` и покрыта тестами без сети.

## Запуск

Локально:

```bash
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN и OPERATOR_IDS
python main.py
```

Docker:

```bash
cp .env.example .env
docker compose up -d --build
```

База и файлы с FAQ и шаблонами лежат в `./data`, папка монтируется в контейнер, поэтому данные переживают пересборку.

VPS через systemd: положить проект в `/opt/support-tickets-bot`, создать там `.venv` и `.env`, затем:

```bash
sudo cp deploy/support-tickets-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now support-tickets-bot
```

Логи: `journalctl -u support-tickets-bot -f`.

## Как подключить группу с топиками

1. Создать группу, в настройках включить «Темы» (Topics).
2. Добавить бота в группу и сделать администратором с правом «Управление темами».
3. Отправить в группу `/chatid` с аккаунта оператора — бот ответит id чата (отрицательное число вида `-100…`).
4. Записать его в `.env` как `SUPPORT_CHAT_ID` и перезапустить бота.

После этого на каждое новое обращение бот создаёт топик и дублирует туда карточку и сообщения клиента. Ответ клиенту — любое сообщение в топике. Карточки в личные чаты операторов из `OPERATOR_IDS` приходят по-прежнему.

## Команды

Клиент: `/start`, `/new`, `/my`, `/faq`, `/help`, `/cancel`.

Оператор: `/tickets [статус] [категория]` (например `/tickets открытые оплата`), `/ticket 1001`, `/stats`, `/ban 123456789` или `/ban 1001`, `/unban …`, `/chatid`.

Команды регистрируются при старте: клиенты видят свой набор, операторы — расширенный.

## Переменные .env

| Переменная | Что значит | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather | — |
| `OPERATOR_IDS` | Telegram id операторов через запятую | — |
| `ADMIN_IDS` | кто может `/ban` и `/unban` | = `OPERATOR_IDS` |
| `SUPPORT_CHAT_ID` | id группы с топиками (необязательно) | пусто |
| `DB_PATH` | путь к файлу SQLite | `data/support.db` |
| `REMINDER_MINUTES` | через сколько минут без ответа напоминать операторам (0 — отключить) | `15` |
| `REMINDER_CHECK_SECONDS` | как часто проверять | `60` |
| `REOPEN_HOURS` | сколько часов после закрытия можно переоткрыть | `24` |
| `TZ_OFFSET_HOURS` | смещение времени для дат в карточках и статистики | `3` |
| `FIRST_TICKET_NUMBER` | номер первого тикета | `1001` |

## Как адаптировать под клиента

- Тексты бота — `bot/texts.py` (приветствие, подсказки, уведомления), описание бота в Telegram — там же (`BOT_DESCRIPTION`).
- Частые вопросы — `data/faq.json`: `question`, `answer` и `keywords`. Ключевое слово — основа слова («оплат» найдёт «оплата», «оплатить»); фраза из двух слов ищется с учётом окончаний («способ оплат» найдёт «способы оплаты»).
- Шаблоны ответов — `data/templates.json`, в тексте работают подстановки `{name}` (имя клиента) и `{operator}`.
- Категории обращений — `bot/services/categories.py`.
- Операторы, напоминания, окно переоткрытия — `.env`.

## Тесты

```bash
pytest
```

Проверяются переходы статусов, подбор ответа из FAQ по ключевым словам, расчёт статистики (время первого ответа, время закрытия, средняя оценка, нагрузка по операторам), форматирование карточки и истории, работа с базой на SQLite в памяти.

## Примерные данные

Ответы в `data/faq.json` (способы оплаты, сроки доставки, контакты, цены) и шаблоны в `data/templates.json` — образец для демонстрации, перед запуском их нужно заменить на данные конкретной компании. Операторы и администраторы в демо — один тестовый аккаунт; оператор может одновременно пользоваться клиентской частью, поэтому весь сценарий можно проверить с одного аккаунта.
